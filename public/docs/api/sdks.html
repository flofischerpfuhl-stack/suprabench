Official SDKs Planned

Skinny official client libraries for Python, TypeScript and Go, shipping after the API is stable in production. Until then, use any HTTP client of your choice — the API is plain JSON over HTTPS, explicitly designed to require no SDK.

Last updated: April 18, 2026 Reading time: 2 min

Status

Not yet available. We will only ship an SDK if it's better than what users would write themselves — otherwise it's just code we have to maintain.

Until they ship

The API is plain JSON; any HTTP client works. Recommended pairings:

  • Python: requests for simple scripts, httpx for async.
  • JS / TS: built-in fetch in Node 18+ and modern browsers.
  • Go: net/http.
  • Curl + jq for shell scripting.

All examples in this documentation use these clients directly, so anything you build today will keep working when the official SDKs arrive — they wrap the same endpoints.

SDK design principles

  • One file each. Read the source in 5 minutes. No clever abstractions, no plugin systems.
  • Typed. Full type hints / TypeScript types / Go structs covering every field.
  • Retries built in. X-RateLimit-* headers and 429 are handled automatically with exponential backoff.
  • No transitive dependencies beyond the standard HTTP client.
  • Bundle size for JS: < 5 KB minified + gzipped. No lodash, no axios.
  • Open source under the same Business Source License 1.1 as the platform.
